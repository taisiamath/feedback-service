# Feedback

Самостоятельный сервис на Python и FastAPI. Сейчас можно создать программу курса
и получить список программ. Данные сохраняются в SQLite и остаются после перезапуска.

## Первый запуск на Mac

Все команды ниже выполняются в Терминале.

Перейти в проект:

```bash
cd /Users/taisiapovarenkova/Documents/Work_uzga/feedback_service/service
```

Создать отдельное окружение Python, если `.venv` ещё нет:

```bash
python3 -m venv .venv
```

Окружение хранит библиотеки этого проекта отдельно от других проектов.

Установить зафиксированные версии библиотек:

```bash
.venv/bin/python -m pip install -r requirements.lock
```

Запустить сервер для разработки:

```bash
.venv/bin/python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8001
```

- `uvicorn` — программа, принимающая HTTP-запросы и передающая их приложению.
- `app.main:app` — объект `app` из файла `app/main.py`.
- `--reload` — перезапуск при изменении кода; используется при разработке.
- `127.0.0.1` — доступ только с этого компьютера.
- `8001` — порт сервера.

Открыть документацию API: http://127.0.0.1:8001/docs

- `POST /courses` — сохранить новую программу курса.
- `GET /courses` — получить список программ с назначенными базой `id`.

POST пока возвращает введённые данные без `id`. Входные поля: `name`, `description`,
`duration_hours`, `teacher`. Название не может быть пустой строкой, продолжительность
должна быть целым числом больше нуля.

Главная страница `/` и адрес `/health` сейчас не реализованы.

## База данных

Функции работы с SQLite находятся в `app/database.py`. При первом запуске проекта
нужно создать таблицу. Из папки `service` выполнить:

```bash
.venv/bin/python -c "from app.database import create_tables; create_tables()"
```

Команда повторно не создаёт существующую таблицу и не удаляет записи. Она не обновляет
структуру существующей таблицы: изменение структуры потребует отдельного шага.

Важно запускать приложение и создание таблиц из папки `service`: пока подключение
использует относительный путь `feedback.db`. Если запустить из другой папки, SQLite
может создать другой файл с тем же именем.

Открыть для просмотра в DataGrip существующий файл
`/Users/taisiapovarenkova/Documents/Work_uzga/feedback_service/service/feedback.db`.
Таблица называется `courses`. Сам файл базы исключён из Git через `.gitignore`.

Остановить сервер — `Ctrl+C` в терминале, где он запущен.

## Файлы

- `app/main.py` — создание приложения и подключение обработчиков курсов.
- `app/courses.py` — класс `CourseCreate` для проверки входных данных и GET/POST курсов.
- `app/database.py` — подключение к SQLite, создание таблицы, запись и чтение курсов.
- `requirements.txt` — допустимые диапазоны версий двух прямых зависимостей.
- `requirements.lock` — точные версии установленных библиотек для повторного запуска.
- `.gitignore` — что не включать в историю Git, в том числе окружение и секреты.
- `docs/workflow.md` — рабочие сценарии из обсуждения с Таисией.

## Как связаны файлы

`main.py` подключает `router` из `courses.py` через `app.include_router(router)`.
`APIRouter` собирает адреса одной части сервиса. Поэтому в `courses.py` используются
`@router.get(...)` и `@router.post(...)` вместо `@app.get(...)` и `@app.post(...)`.
Адреса и результат запросов остались прежними.

При POST код `courses.py` проверяет входные данные через `CourseCreate`, затем вызывает
`save_course` из `database.py`. При GET вызывает `get_all_courses`. SQL остаётся
в `database.py`, а обработчики HTTP-запросов — в `courses.py`.

Пока класс проверки и обработчики курсов находятся вместе: код небольшой и относится
к одной функции сервиса. Отдельные слои для бизнес-логики, хранения каждой сущности
и файлы для студентов появятся, когда для них будет реальная задача.
